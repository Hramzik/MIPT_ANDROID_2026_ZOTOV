# Домашнее задание по курсу MIPT ANDROID 2026: Kotlin Coroutines

Практические задания по корутинам Kotlin в контексте Android-разработки.

## Структура проекта

```
src/
├── main/kotlin/tasks/ <- реализуйте код здесь
│   ├── Task1.kt  
│   ├── Task2.kt
│   ├── Task3.kt
│   ├── Task4.kt
│   └── Task5.kt
└── test/kotlin/ <- юнит тесты, трогать запрещено
    ├── Task1Test.kt 
    ├── Task2Test.kt
    ├── Task3Test.kt
    ├── Task4Test.kt
    └── Task5Test.kt
```

Каждый файл `TaskN.kt` содержит интерфейс и класс-заглушку с `TODO("Not yet implemented")`. Нужно реализовать методы класса так, чтобы все тесты проходили.

## Задания

| # | Название | Файл | Баллы |
|---|---|---|:---:|
| 1 | Exponential Backoff Retry | `Task1.kt` | 1 |
| 2 | Параллельная загрузка с переключением потоков | `Task2.kt` | 2 |
| 3 | SearchViewModel (StateFlow + SharedFlow) | `Task3.kt` | 2 |
| 4 | Deduplicating Loader | `Task4.kt` | 3 |
| 5 | Реактивный поисковый пайплайн | `Task5.kt` | 2 |
| | **Итого** | | **10** |

## Правила

- Изменять можно **только** файлы `Task1.kt` – `Task5.kt`
- Тестовые файлы изменять **нельзя**
- Списывать задания нельзя. На экзмене любую задачку из этого блока я могу спросить устно, при невозможности объяснить свой код вы получите `-10` баллов за каждую списанную задачку
- Запрещено использовать `Thread.sleep` — только `delay`
- Необходимо склонировать репозиторий к себе, выполнить задания и сделать merge-request с решениями в своем репозитории
